# 性能工程记录:测量方法、实测数据与已知边界

本文档所有数字来自 2026-10-12 修复轮次后的实测,环境与复现命令随数据附上。
历史版本的无参数数字已废弃——没有负载、环境与统计口径的数字不可比,也不可信。

## 测量环境

- Apple Silicon (arm64), 10 核, macOS
- 编译:clang++ -std=c++17 -O2 (默认 Makefile)
- 拓扑:BA 无标度图,300000 节点 / 5999790 边(平均度 ~40,hub 度数千级)
- 负载:16 并发客户端,混合 55% 共同好友 / 25% 二度 / 10% 距离 / 5% 加边 / 5% 删边
- 预热:2 秒纯查询(不含更新,保证两引擎从同一图状态开始测量)
- 统计:吞吐 = 完成量 / 真实墙钟(含排空);延迟为对数桶直方图,分位数输出桶上界(保守)

## 客户端并发模型与 Little 定律交叉验证

压测客户端为**开环轰炸模型**:每次 Submit 成功后立即提交下一请求,
不等待回调完成(过载时按指数退避重试,503 计入 shed)。单客户端在飞
请求数不设上限,系统级在飞受计算队列容量(4096)与 503 快速失败约束。

Little 交叉验证(均匀负载):50860 qps × 46.0ms ≈ **2340 平均在飞**,
低于队列容量 4096,与 5% 的 shed 率一致,吞吐与延迟数据自洽。
若采用单请求闭环客户端(每客户端至多 1 在飞),理论吞吐上限为
16 / 0.046s ≈ 348 qps——两组数字的差异全部来自客户端模型,对比
不同系统的数据时必须先对齐该口径。闭环(扫容量)与受控到达率
(看过载行为)两种模式的系统化对照在后续清单。

## 本轮性能修复记录(profiling → 修复 → 验证)

1. **回收-分配锁竞争**:统一 COW 后 Retire 风暴使 Sweep 逐个 Deallocate
   与分配热路径在 SlabPool 档位锁上互锁(sample 实测 628/1779 采样等待)。
   修复:按池分组批量归还,每档一次锁交接。建图 71s → 15.7s。
2. **分配热路径防御性校验**:每次分配线性扫描页列表验证空闲头/next 的
   页归属,O(页数) 开销。修复:热路径只留 O(1) 魔数校验,完整校验
   移入 ValidateFreeBlock 诊断接口。
3. **503 断连风暴**:过载即断连放大重连压力,且压测端被 SIGPIPE 杀死
   (exit=141)。修复:503 保留 keep-alive;客户端忽略 SIGPIPE。
4. **SlabPool 账本原子化**:不同档位锁并发修改同一计数器的数据竞争,
   bytes_in_use 曾下溢出 17TB 荒谬值。
5. **重建尾容量按度数增长**:固定 8 槽导致高度节点 O(d^2/8) 反复全量重建。
6. **bench 口径**:预热纯查询;吞吐分母含排空的真实墙钟;排空条件用
   测量批次计数;分位数输出桶上界。

## 消融边界声明

1.48x 是**整引擎对照**(压缩邻接+尾缓冲+分桶锁+COW/EBR+Slab+工作区
复用的整体 vs vector+全局锁+memset 基线),不是压缩存储单一变量的
贡献;热点 0.73x 同理是整体回退,profiling(sample 抓栈)显示主要
来源是 SecondDegreeBfs 的 varint 解码与结果排序,但「解码/排序/锁
竞争/内存访问」各因素的**独立贡献占比尚未通过单变量消融量化**,
是后续清单项。引用本数据时应表述为「引擎整体对照」,不宜归因于
单一机制。

## 复现命令

```bash
# 均匀负载双引擎对比
./bin/bench --nodes 300000 --seconds 25 --clients 16 --no-redis --zipf 0

# 热点负载(0.73x 边界场景)
./bin/bench --nodes 300000 --seconds 25 --clients 16 --no-redis

# HTTP 全链路
./bin/server --nodes 300000 --port 8080 --no-redis &
./bin/bench --nodes 300000 --seconds 15 --clients 16 --no-redis --zipf 0 \
    --http 127.0.0.1:8080

# 回归防线
make test && make fuzz && make asan && ./bin_asan/tests
```
